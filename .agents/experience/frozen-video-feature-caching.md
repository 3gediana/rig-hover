# 冻结特征缓存：8 GB 笔记本上跑 8 族模型 × 17 数据集 × 3 种子的唯一可行方式

**适用**：比较"时序/融合/决策"结构（不是比较视觉编码器），且视频解码是主要成本。

## 现场

要在 RTX 5060 Laptop（8 GB，实际可用 ~5.5 GB）上比较
mlp / gru / lstm / cfc / mamba / deltanet / dsm / dsm_slot 八个时序核心，
数据是 UCF101（6261 条）、Charades（1400）、DAVIS（90）、MOT17（6）。

## 做法（实测可行）

1. **视觉编码器全程冻结、只跑一次**：`openai/clip-vit-base-patch16`，224 px，fp16。
   实测 **500 img/s @ batch 128（0.86 GB 显存）**，batch 256 也只 1.52 GB。
   ⇒ 编码器不是瓶颈；**解码**才是。UCF101 全部 ~58 万帧 ≈ 20 分钟 GPU。
2. **每序列一个 npz**，存 `feat [T,768] f16` + `tok [T,4,768] f16` + `t [T] f32` + 标签。
   UCF101 全量约 4.5 GB（`G:\stream_memory_data\features\`）。
3. **训练时只加载标签需要的时间步**，时序核心是几十万参数的小网络，
   于是 8 族模型 × 17 数据集 × 3 seeds（400+ run）在一夜内跑完。
4. **同参数量对齐**：写一个 `build_core_matched(name, in_dim, target_params)`，
   对 hidden 做二分搜索，落点在目标 ±0.5% 内（18/18 组）。
   这样"只有时序算子不同"这个对照才成立。

## 关键收益

- 对照干净：所有模型吃**同一份缓存特征**，不会出现"某个模型顺手把编码器也训了"。
- 提速 100×：一次编码换几百次训练。
- 可复现：特征目录 + 编码器 tag（`clip-vit-base-p16-224-f16-2x2tok-v1`）写进 manifest，
  版本一变就换 dataset 名，禁止混用。

## 代价 / 边界

- **不能联合微调编码器**（项目里的"阶段 3"因此一直没做）。要微调就必须放弃这个速度。
- 缓存的是**固定采样**的帧；换采样率要么预存多份，要么在特征序列上做重采样
  （本项目用后者：全部扰动都在特征+时间戳上做，等价于"同一物理过程的不同采样"）。
- 若任务依赖低层像素细节（小目标、纹理），CLIP CLS 特征可能不够——本项目的
  真实动作识别里 **无记忆 MLP 用 CLS 特征就有 0.812**，说明特征很强；
  反过来说，这也让"是否需要记忆"变得难以测出（见另一条笔记）。
