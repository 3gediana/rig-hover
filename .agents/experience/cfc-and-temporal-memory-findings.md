# 流式记忆网络实测结论：CfC 不可用、衰减作用任务依赖、两项能力互相挤占

**适用**：这个项目（文文/RIG-Hover）若再要继续做"视频流决策网络"，先读这一条，
不要重复已经做过的 400 个 run。全部数字来自
`D:\robot_work\stream_memory_research\reports\中文总结报告.md`（1071 行）与
`runs/*/metrics.json`。

## 1. CfC 不能当最终部署模型（最硬的结论）

CfC（ncps 口径，`timespans` = 真实 Δt）在**所有需要整合一段时间的任务上 ≈ 随机**：

| 任务 | CfC | 参照 |
|---|---|---|
| 真实视频时序方向判别（原始帧序 vs 倒放） | **0.5004** | 随机 0.500；逐帧 MLP 0.5000 |
| 合成节律判别（0.2 s vs 0.6 s 双敲） | 0.483 | 随机 0.500 |
| 合成多击计数（1/2/3 下） | 0.336 | 随机 0.333 |
| 不规则采样计数 | 0.342 | 随机 0.340 |
| **UCF101 动作识别（101 类）** | **0.7989** | **无记忆 MLP 0.812** |

**在真实动作识别上它比"什么都不记"还差 1.2 个百分点**（CI 不跨 0）。
结构原因：`h_new = ff1·(1−t) + t·ff2`，两个 tanh 的凸组合 ⇒ 隐状态被限制在 (−1,1)，
且没有 h 的线性自环 ⇒ 长期保持能力受限。

**它也**不是时间标度问题：给它加 `dt_scale`（把秒换成无量纲 timespan）反而更差
（0.596 → 0.490 → 0.439）。所以"CfC 调一下就好"这条路已经排除。

## 2. 多时间常数衰减是"时间的频域表征"，作用任务依赖

同一份参数下：

| 任务 | 4 组多尺度衰减 Λ=[8,2,0.5,0.02]/s | 无衰减 | 单时间常数 |
|---|---|---|---|
| 多击计数 | 0.553 | **0.889** | **0.333 = 随机** |
| 真实时序方向 | **0.943** | — | **0.500 = 随机** |

- 计数/保持类：衰减**有害**（它销毁历史）。
- 顺序/方向类：衰减**必需**（它是判断"往哪个方向流"的滤波器组）。
- **单时间常数是最差的配置**，比"完全无记忆"还糟（一致地抹掉历史）。

推论：**正确设计是同时保留一条无衰减通道（管保持）+ 一组多时间常数通道（管顺序）**。
本项目实现了 `src/models/dual.py`（`ret_kind='delta'|'gru'`）验证这一点。

## 3. "保持"与"时序方向"在固定容量下互相挤占

| 模型 | `recall_multi`（同时记住 8 个对象） | `ucf101_order`（时序方向） |
|---|---|---|
| gru | **0.852** | 0.928 |
| hybrid（GRU 稠密状态 + 多时间尺度 order bank）@1.11× | 0.804 | 0.932 |
| hybrid @2.05× | 0.825 | **0.942** |
| dsm（纯 delta 快记忆 + 慢状态） | 0.693 | **0.943** |
| cfc | 0.415 | 0.500 |

**换 retention bank 类型：保持 +11 点，时序方向 −1.1 点。**
这不是调参问题，是**容量竞争**——这也是为什么整个项目找不到"两个维度同时赢"的模型。

另外已排除的三个解释（都实测过、都无效）：
记忆维度 64→128→256（无改善）、槽位 12×64→16×128（无改善）、
逐对象 rank-K 写 `use_tok`（0.673，反而更差）。
**真正的差别在"稠密递归状态"与"关联式快记忆"之间，不在容量大小。**

## 4. 任务设计比模型选择更重要（做实验前先看这条）

- **UCF101 动作识别不是记忆任务**：逐帧 CLIP 特征下无记忆 MLP 就有 0.812，
  所有循环模型只高 0–5 点。在这上面比较"记忆机制"是温室刷分。
- **要做的是"判别信息只在时间轴上"的任务**。已验证的构造：
  **同一段视频的原始帧序 vs 倒放帧序**（帧集合完全相同、时间戳递增），
  逐帧 MLP 被构造性地钉在 0.500，CfC/DeltaNet 也恰好 0.500，
  只有真正用时序的模型能上去（本模型 0.943，gru 0.928）。
  代码：`scripts/build_ucf_order_task.py`。
- 合成任务必须做**单帧分类器对照**：本项目的时间模式任务让单帧 logistic 回归只有
  0.34/0.50/0.54/0.24（chance 1/3,1/2,1/2,1/4），才敢说"必须整合窗口"。
- 合成任务测试集 **20 条序列太少**，配对 bootstrap 只有 60 对，功效不够；
  真实任务 ≥1000 条才够。

## 5. 仍未解决的、值得继续的方向

1. 真实视频的**节律/速度/事件顺序**基准（每类 ≥500 测试序列）——现有真实任务只有
   `ucf101_order` 一个干净时序任务。
2. 增加总容量或改训练目标来打破 §3 的权衡；**继续换衰减策略已经没有意义**。
3. Charades 事件检测需要重设（3.5% 正样本 + BCE 0.5 阈值 + 980 条序列 ⇒ F1 全 0），
   要类别平衡采样 + 每类阈值搜索。
4. 机器人真机数据仍然没有，机器人域只在合成/离线层面覆盖过。
