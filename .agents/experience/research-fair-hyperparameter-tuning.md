# 只给自己的模型调超参，会稳定制造假优势

**适用**：任何"我们的模型 vs 基线"的对比实验（不是只限机器学习）。

## 现场

流式记忆网络项目里，`synth_pattern_rate`（分辨两次敲击间隔 0.2 s vs 0.6 s）上：

- 基线默认配置（lr=3e-3，所有模型统一）：`gru` 0.850，本模型 0.833 —— 打平。
- 我把**本模型**的记忆维度提到 256、学习率降到 1e-3、warmup 加到 6：
  本模型 **[1.000, 0.979, 1.000] = 0.993**，看起来以 **+14.3 个百分点**超过 GRU，
  按序列配对 bootstrap 的 95% CI 是 **[+0.071, +0.219]，不跨 0**。
- 差一点就把这写成"第二个胜出维度"。

## 陷阱

**只对挑战者做超参搜索、对基线用默认值**，得到的是一个**调参预算不对称**的比较，
不是架构比较。学习率这类参数对不同的循环结构最优点差得很远：
`gru`/`deltanet` 在 lr=1e-3 下恰好是 1.000，在 lr=3e-3 下只有 0.850 / 0.707。

## 验证后的做法

**把所有基线放到我们模型的最优超参上重跑一遍**。实测结果：

| 模型（全部 lr=1e-3, warmup=6, 3 seeds） | acc |
|---|---|
| gru | **1.000** |
| deltanet | **1.000** |
| 本模型 | 0.993 |
| lstm | 0.979 |
| mamba | 0.955 |
| cfc | 0.467 |

那个 +14.3 点的"胜利"**归零**，本模型实际排第 4。假设被撤回。

## 落地规则

1. 每个任务上**所有模型共享同一份超参搜索预算**，并且**只用验证集选择**。
2. 报告里必须写清"每个模型的学习率是怎么定的"。本项目最终用的协议是：
   两档 lr（2e-3 / 1e-3）都跑一遍，按 **val** 选每个模型自己的最优档，
   再比较对应 test —— 这样对比才是同预算的。
3. 一个"胜利"在写进结论之前，先问一句：**基线的这个超参是谁选的？**

## 边界

这条规则不否定"模型确实有超参敏感性差异"这一现象本身——它只否定把
**不对称的搜索**当成**架构优势**。若要说"我们的模型对超参更鲁棒"，
必须**两边都搜过**，再展示搜索空间上的分布差异。
