## 2. 方法

### 2.1 总体结构

```
像素流 ──▶ 冻结 CLIP ViT-B/16 ──▶ 768-d CLS (+4×768 patch tok)   逐帧、无状态
                                        │
                                  x_t, Δt_t（真实秒）
                                        ▼
                          ┌──────────────────────────────┐
                          │  时序核心 (7 种之一)          │  全网唯一有状态部分
                          └──────────────────────────────┘
                                        │ o_t
                                        ▼
                          共享任务头 MultiTaskHeads       逐帧、无状态
                          (LayerNorm + 2×MLP + 线性头)
                                        │
                                   logits
```

所有模型共用**同一个 encoder、同一个 head、同一个输入契约**
（`src/train/factory.py:198` `StreamModel`），差别只在中间的 core。

### 2.2 本模型（DSM）的方程

逐帧，`Δ` = 真实秒（clamp 到 `dt_clamp_max=10`）：

**慢状态（物理时间精确零阶保持）**

```
g_h = exp(−Γ_h · Δ)                          Γ_h 每维一个，τ_h ∈ [0.2, 2] s
h⁻  = g_h · h
g   = sigmoid(W_g [z, h])
h   = h⁻ + g · (tanh(W_u [z, h⁻]) − h⁻)
```

**快记忆（多时间尺度衰减 + 残差/Householder 写）**

```
Λ   = softplus(raw)[group(d_v)]               G=4 组，速率 [8, 2, 0.5, 0.02] /s
M⁻  = M · exp(−Λ · Δ)                          衰减是 Δ 的纯函数
q,k,v = W_q[z,h], unit(W_k z), W_v[z,h]
r   = read(M⁻, q)                             线性 Mq / 双线性 2-hop
e   = v − r
β   = sigmoid(w·[z,h,r,log1p Δ] + w_s·log1p‖e‖)   写强度 ← surprise
M   = M⁻ − β(M⁻k)kᵀ + β v kᵀ
o   = read(M, q)
out = LayerNorm(MLP([h, o, z]))
```

**streaming 状态实测**：`h [B, 192]` + `M [B, 64, 64]`，每流 4288 个数，**与视频长度无关**。

**参数分解（`ucf101_order` 那套配置实测）**：core 483,724 + heads 41,858 = **525,582**。

### 2.3 每个组件承担什么（由消融判定，而非设计意图）

| 组件 | 被消融后发生什么 | 判定依据 |
|---|---|---|
| 多时间尺度衰减（4 组） | `ucf101_order` 0.943 → **0.500（随机）** | §7.6 第 23 项 |
| 多时间尺度衰减（4 组） | `synth_pattern_count` 0.553 → **0.889（去掉反而更好）** | §7.6 第 20 项 |
| 慢状态 `h` | 仅快记忆（`deltanet`）在 `ucf101_order` = 0.4999 | §7.6 第 3 项 |
| delta 残差写 | 换成加性外积 `write_rule="outer"` 更差 | `ablations_v1` |
| 真实 Δt 结构项 | 在纯回忆任务上几乎无差（0.913 vs 0.921） | §7.6 第 5 项 |

### 2.4 被证伪的设计主张（保留在案）

| 主张 | 实测反证 |
|---|---|
| 矩阵快记忆的容量优势会在多目标回忆上兑现 | `recall_multi` 0.693 vs GRU 0.852 |
| 多时间尺度衰减是节律判别的优势来源 | 充分调参后 GRU/DeltaNet 均达 1.000 |
| CfC 需要无量纲 timespan 才公平 | 加 `dt_scale` 后更差：0.596 → 0.490 → 0.439 |
| 在纯保持任务上本模型能赢过 GRU | 结构上不能：GRU 隐状态无强制衰减 |

## 4. 数据

### 4.1 受控合成任务（70 个数据集 / 5428 序列，oracle 可验证）

构造原则：观测只含"当前可见/当前发生"的信息，标签是每步真实潜状态 ⇒
无记忆模型在需要整合的步骤上必然失败。

| 任务族 | 内容 | 无记忆基线 | 随机水平 |
|---|---|---|---|
| `recall_single` | 单目标消失后读回原值 | 0.000 | ≈0 |
| `recall_multi` | 8 目标各自独立变化 | 0.000 | ≈0 |
| `change_detect` | 该保持时保持、该更新时更新 | 0.000 | ≈0 |
| `vanish_reappear` | 目标离开后恢复身份 | 0.042 | 0.062 |
| `event_seq` | 稀疏事件后长期保持 | post-event 0.000 | — |
| `pattern_count` | 1/2/3 次敲击 | 0.333 | 0.327 |
| `pattern_order` | A→B vs B→A | 0.500 | 0.471 |
| `pattern_rate` | 两击间隔 0.2 s vs 0.6 s | 0.500 | 0.479 |
| `pattern_count_irregular` | 个数 + 原生不规则 Δt + 30/50/70% 掉帧 | 0.340 | 0.380 |

`pattern_*` 族的诚实性构造：**最后一拍时间对齐、幅度在每个脉冲重置**，因此在被打分的步骤上
所有通道分布与类别无关 —— 单帧 logistic 分类器实测 0.342 / 0.503 / 0.535 / 0.236
（chance 分别为 1/3、1/2、1/2、1/4）。**类别证据只存在于更早的脉冲串里。**

## 5. 实验协议

| 项 | 做法 |
|---|---|
| 切分 | 按视频 / 按序列 / 按 session；`Manifest.check_split_disjoint()` 强制断言；倒放变体与扰动变体继承原 split |
| 因果性 | 单元测试强制：扰动未来帧，过去输出**逐位不变** |
| 调参 | 每个模型在自己的**验证集**上选学习率（候选 lr=2e-3 / 1e-3）；测试集不参与选择 |
| 参数量 | **未做匹配**（见更正 C1）；同一 suite 内所有模型共用 `hidden` |
| 统计 | 序列级配对 bootstrap（4000 次重采样）；仅在模型保存了 `per_seq_test` 的任务上可用 |
| 执行 | **单进程串行**。并发 torch 进程会耗尽本机 commit 内存并产生假崩溃（`WinError 1455` / `bad allocation` / `cudaErrorAlreadyMapped`） |
| 辅助损失 | 真实视频任务上 `aux_num_scale=0`（关闭），对同一任务上所有模型一致 |
| 训练预算 | 真实视频 15 epoch、batch 32、patience 5、T_max=48（order）/96（action） |

### 7.7 能力权衡与容量扫描

**权衡（固定参数预算下"保持"与"时序方向"互相挤占）：**

| 模型 | `recall_multi` | `ucf101_order` | 参数量（各自任务） |
|---|---|---|---|
| gru | **0.852** | 0.928 | 382k / 599k |
| dual（GRU 保留银行 @1.13–1.28×） | 0.804 | 0.932 | 489k / 679k |
| dual（@1.93–2.24×） | 0.825 | 0.946 | 856k / 1,156k |
| dual（@2.89–3.46×） | 0.834 | 0.946 | 1,320k / 1,732k |
| **dsm（纯 delta 记忆）** | 0.693 | **0.943** | 475k / 526k |
| dsm_slot | 0.726 | 0.948 | 463k / 514k |
| cfc | 0.415 | **0.500** | 159k / 155k |

**把 retention bank 换成 GRU**：保持 0.693 → 0.804（+11.1 点），
时序方向 0.943 → 0.932（−1.1 点，掉到 GRU 水平）。
**把参数量加到 3.46×**：保持只到 0.834，**仍低于 GRU 的 0.852**；
时序方向 0.946（+0.3 点，与 2.24× 相同）。
⇒ 容量增加未消除权衡，且未在任一侧超过对照。

**被排除的解释（全部实测，全部无改善）：**
`mem_dim` 64→128→256（0.693 / 0.698 / 0.689）；slots 12×64→16×128（0.726 → 0.734）；
`use_tok` 秩-K 写（0.673 / 0.690）。

### 7.9 因果前缀曲线（在线性能）

### 7.10 时间打乱对照

每个合成任务都有 `*_shuffled` 变体（观测行随机置换、标签不变）。

## 11. 本报告与原报告（`中文总结报告.md`）的差异：更正清单

以下三条是整理客观报告时发现的**原报告不准确之处**，在此更正。

**C1 — "参数匹配"未实施（原报告措辞过强）**
原报告多处暗示各模型参数同量级/已匹配。实际上 `ucf101_order` 这一套**没有做参数匹配**：
`hidden` 统一为 192，最终参数量从 CfC 的 154,950 到 LSTM 的 783,750，相差 **5.06 倍**；
本模型 525,582，比 GRU 少 12%、比 LSTM 少 33%、比 Mamba **多 28%**。
判据 6（不靠 10× 参数）仍然满足，但"参数匹配"这个说法不成立。

**C2 — `ucf101_order` 里 "dsm lr=1e-3" 那一行不是 base 配置**
原报告 §5.13 表中 "dsm lr=1e-3 → val 0.9426 / test 0.9313" 对应的实际 run 是
`ucf101_order__dsm__nd256_lr1e3__s0/s1`，其配置为 **`mem_dim=256, decay=False`**（747,534 参数），
不是 base 的 `mem_dim=64, 4 组衰减`（525,582 参数）。
因此"每个模型都拿到同样的学习率搜索预算"对 gru / mamba / lstm / deltanet / cfc 成立，
对 **dsm 不完全成立**（它的 lr=1e-3 行换了一个更宽且关掉衰减的配置）。
由于 dsm 在验证集上选中 2e-3（0.9594 > 0.9426），**7.2 节的表内数字全部来自 base 配置，结论不受影响**。

**C3 — 种子数与参数量记法**
原报告 §5 写"`ucf101_order` 的 dsm 只跑了 1 个 seed"，实际有 s0/s1 两个
（0.9442 / 0.9416，均值 0.9429）。
原报告 §5.20 引用 dsm 为 474,540 参数，那是合成任务（`in_dim=336`）的配置；
真实视频 order 任务上 dsm 实际为 **525,582**。本报告一律使用各任务的实际 run 值。
