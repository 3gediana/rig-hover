# 视觉特征流是否足以支撑机器人决策：审计与探针结果

> 日期：2026-11-04  
> 范围：核对已有视觉编码器特征、机器人录像、像素端到端实验及监督/切分；补做一个限定于单段机器人录像的局部特征探针。  
> 没有烧录/修改固件，没有访问机器人控制端点，没有下载数据。现有机器人图像离线处理。

## 结论先行

**当前证据不能证明视觉编码器输出的连续特征流足以支持本机器人需要的决策。**

更精确地说：

- 冻结 CLIP 特征会随时间变化；这只说明编码随输入变化，不说明它编码了握拳、敲击阶段、离开/返回或敲击目标。
- 同一段离开/返回录像的后半段上，CLIP 的 4 个 patch tokens 能以粗略方式区分“可见/离开/过渡”标签；但 16x16 原像素也得到相近分数，而且训练与测试来自同一人、同一房间、同一录像。这是样片内诊断，不是独立泛化，更不是充分性证明。
- 现有敲击、挥手机器人录像没有逐次事件边界/阶段标签；敲击点无坐标真值。不能给“敲击事件特征可分性”或“计数决策”报有效分数。
- 已有机器人 pixel-event LOO 数字存在切分和评估错误，不能作为 held-out 证据。
- 因此，最重要的实验结果是**当前机器人域数据不足以判定特征充分性**。这不是说 CLIP/YOLO 特征肯定不行，也不是证明它们够用。

## 用户场景对应的必要信息

机器人要做到：1–2 米看人脸；握拳时注意拳头；桌面敲两下后锁定敲击目标并移动、即使手已离开；到位后停留并回看人脸。需要验证的视觉信息至少包括：

1. 人/脸/手的当前定位与可见性；
2. 握拳与其他手势的区分；
3. 敲击的逐次阶段、完成时刻、次数和接触位置；
4. 人离开、重新进入以及身份/目标状态连续性；
5. 图像观测到敲击目标方位/位置的映射。

只测 UCF101 通用动作分类、正序/倒序、特征相邻相似度或整段脚本类别，不足以覆盖以上契约。

## 已有数据与编码器

| 数据/接口 | 实际内容 | 本次用途与限制 |
|---|---|---|
| `evidence/sessions/` | 10 段机器人相机录像，每段约 189–202 帧、20 秒、240x240 灰度、约 10Hz；全部约 0.5m、正面、夜间；每类单一 take | 原始像素可重编码。样本覆盖 fist、knock、wave、lean_out 等，但只有整段脚本标签 |
| `robot_gesture` CLIP 缓存 | 28 chunks / 1,792 帧；每帧 CLS 768 维 + 4x768 patch tokens；每类一个 session；源录像实际约 1,987 帧，缺 195 帧，knock cache 只覆盖 128/189 帧 | 可做无监督特征变化统计；chunk split 跨同一 session，不能用于有效泛化准确率 |
| CLIP encoder | `openai/clip-vit-base-patch16`，224输入；提供全图 CLS、2x2 pooled patch tokens，另有可选 ROI API | 通用预训练视觉基线；机器人 cache 无 ROI 特征。其特征是否保留机器人事件信息需相应标签验证 |
| YOLO26n-pose | 本地权重可得到 COCO-17 人体关键点及 P3/P4/P5/CLS 特征 | 提供人体/姿态先验；没有手指关键点，不能仅凭姿态保证拳型或敲击阶段 |
| Charades pixel | 700段像素视频，逐帧区间活动类和 onset | 通用真实事件边界代理，不是桌面敲击/机器人交互 |

只读脚本审计了 `robot_gesture` 28/28 个缓存，无文件读取错误：

| 指标 | 数值 |
|---|---:|
| CLS lag-1 cosine，约 0.1 秒 | 0.939 |
| CLS lag-2 / lag-4 / lag-8 / lag-16 cosine | 0.919 / 0.907 / 0.903 / 0.890 |
| CLS lag-1 差值 L2 | 2.412 |
| patch-token lag-1 cosine | 0.971 |
| patch-token lag-1 差值 L2 | 4.761 |

这些数只表示特征在变化且相邻帧高度相关。变化可能来自手、人、相机运动、光照、压缩或背景；它不识别哪一种变化对应敲击/握拳。

## 单段离开/返回录像的局部探针

为了确认已有表示是否至少带有“人可见性”的信号，我检查了 `lean_out_d0.5_front_night_182257` 的 240x240原图联系表，并按粗略可见状态划分时间段：可见、离开/不可见、进出过渡。将前 96 帧训练、后 96 帧测试，用同一录像的冻结特征训练轻量逻辑回归。过渡帧标注仅凭联系表粗定，结果不用于泛化主张。

| 输入特征 | 同片后半段准确率 | Macro-F1 |
|---|---:|---:|
| 16x16 灰度原像素 | 0.781 | 0.703 |
| CLIP CLS 当前帧 | 0.635 | 0.670 |
| CLIP 4x768 patch tokens | 0.812 | 0.807 |
| CLS 当前帧 + 一帧差分 | 0.677 | 0.702 |
| CLS 因果 5 帧均值 | 0.604 | 0.618 |
| 5 帧均值 + 一帧差分 | 0.604 | 0.622 |

测试段类别支持数为 absent/visible/transition = 21/53/22，测试段多数类准确率为 0.552。

**能支持的有限观察**：这段录像里 CLIP patch tokens 和原始像素都包含可读的可见性线索；CLS 单帧弱一些，简单平滑/差分没有改善。  
**不能支持**：跨 session 的离开/返回检测、人物身份连续性、事件后目标保持、可否打扰机器人；模型可能利用固定房间布局、摄像头视角、同一人的外观或长时背景差异。单录像按时间块划分仍有显著域泄漏风险。

可复跑脚本：`agent_feature_probe/probe_leave_return.py`；结果：`agent_feature_probe/leave_return_probe.json` 与 `agent_feature_probe/leave_return_probe.md`。联系表位于 `agent_feature_probe/contact_sheets/`。

## 既有实验的有效性审计

### Robot pixel-event 的所谓 LOO

它不是有效留一 session 测试：

- `RobotSessions(held_out)` 的实现是从 records 中**排除**这些 session；训练脚本把同一个排除后的 dataset 同时用作 test，并令 `va=te`。
- `eval_robot` 又按全部 session 循环，构造方式仍排除 held session；命令行调用参数数量也不匹配，实际日志报 `TypeError`。
- f0–f4 metrics 的 val/test 数值逐字段相同，且均无 `eval.json`；f5 未完成。

因此旧 `gesture_acc≈0.16–0.18`、`presence macro-F1≈0.82–0.886` 是共享训练源上的内部指标，不是 held-out 泛化结果。presence 标签只是空镜=absent，其余所有脚本整段=present，不是逐帧离开/返回真值。

### Robot CLIP chunks

`robot_gesture.json` 把每个唯一 session 的连续 chunks k0/k1/k2 分给 train/val/test。同类只有一个独立脚本 take，因此任何从这个 split 得出的 class probe 都可能读取到同一录像的背景、人物与光照，不能当跨 session 性能。

### Charades pixel-event

真实 Charades 测试视频上的 pixel_event mAP 0.0452、phase macro-F1 0.0673、onset F1 0.0952；frame-CNN/GRU phase F1 约 0.0845/0.0847，onset 同为 0.0952。无图像全正预测 phase F1 已为 0.0847；16x16池化像素逐帧线性 mAP 0.0558。每模型仅一个 seed。该代理任务没有证明视觉事件检测有优势；count exact 约0.92受大量零计数及稀少重复事件影响，不能解释为敲击计数能力。

### UCF101

- 普通 UCF101 action 的 CLIP CLS 逐帧 MLP 约0.812，说明常见视频动作中有很强静态/单帧线索，不等于机器人精细事件理解。
- UCF101 正序/倒序任务同源视频的帧集合一致，MLP约0.500、DSM 0.9429、GRU 0.928。这有效证明该特定任务的冻结 CLIP 流包含通用时序顺序信息，但不证明“敲了几下”或“离开后仍能走向目标”。

## 判定

| 问题 | 结论 |
|---|---|
| 视觉表示是否随视频变化？ | 是，CLIP CLS/patch tokens均有时间变化；但语义未定 |
| 当前特征是否可支持单片段人可见性状态？ | 有样片内信号；局部探针里 patch token 和低分辨率原像素均可读 |
| 是否证明特征适合握拳、敲击阶段/次数、敲后目标位置？ | 否；标签和坐标缺失，不能估计 |
| 是否证明跨人、跨距离、跨光照及部署泛化？ | 否；机器人数据仅一个人/一个距离/一种光照，且历史 split 泄漏 |
| 现有 robot LOO / presence 指标能否作依据？ | 不能，数据集和评估程序均有 protocol bug |
| 视觉特征充分性最终结论 | **未验证；现有证据不足以判断** |

## 下一个有效验证需要什么

要判断“决策网络需要的特征是否真的被保留”，最低限度要有独立录制 session 和逐帧/逐事件标签，而不是继续在旧的脚本类标签上训练：

- 多次独立录制握拳、张掌、无手和拳头短暂遮挡；同一人及不同人都要出现在多个 split。
- 敲击每次的 approach/contact/rebound/completion 时间、敲击次数、桌面目标坐标；增加手在桌面附近移动但未敲击的负例。
- 挥手每个完整来回的边界和计数；速度、方向、停顿不同。
- 离开/返回的逐帧 visible/leaving/absent/returning 标签、身份以及重现后是否同一人。
- session/人物/拍摄条件级切分；在同一冻结视觉编码器下比较全图 CLS、patch tokens、手部/人脸 ROI、YOLO pose、原像素/简单运动差分；逐帧探针与0.3–0.5秒因果窗口、完整因果序列分别报告。
- 以真实测试事件级 precision/recall/F1、计数 MAE/准确率、检测延迟、敲后目标坐标误差为验收，不以帧分类准确率代替闭环策略质量。

现有材料里最值得保留的是：原始机器人像素已保存，YOLO/CLIP编码器可重跑；它为干净的标注和 session-level split 提供了数据起点，但不构成目标行为的训练集。
