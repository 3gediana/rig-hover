# 附录：航向环阻尼 `k_dyaw` 与命令速率限幅

> 复现：`python scan_dyaw.py --seeds 6`、`python diag_sep.py --exp all`、
> `python ../train/probe_smooth.py`。所有数字是仿真值，不是真机实测。
> 本文只动固件与仿真，没有重训网络。

## 0. 一句话

1. D 项按任务给的式子（`- k_dyaw*yaw_rate`）加进去，起阻尼作用的取值是**负的** `k_dyaw`：
   `k_dyaw = -0.2 ~ -0.3` 把航向环 ζ 从 **0.084 提到 0.26~0.35**，教师/PD 两条
   控制器的跟踪误差和成功率**按数量级改善**（教师 ε 11.7°→6.4°，成功率 77%→97%）。
2. 但 **头身分离比只从 0.71 到 0.90**（CfC，`k_dyaw=-0.2`），仍然 < 1.4。
   把 `yaw_rate` 里的头部角速度减掉之后能到 **1.09**（`k_dyaw=-0.2`）/ **1.57**
   （`k_dyaw=-0.8`，代价 ε +9%、成功率 -4pt）。**「只动头」没有做到。**
3. 没做到的**主要**原因不是阻尼不够，而是**机身的角度行程里大部分是策略自己下的
   `vyaw` 指令**：小误差区里 `head_share_cmd = 0.383`，即指令侧 62% 的动作是转机身。
   D 项只能压掉"振荡"那一部分，压不掉"被指令要求的那一部分"。
4. 把策略的 `vyaw_des` 压到 0（消融，不是固件改动）后分离比 **5.49**；再加上
   "D 项用机身角速度"，分离比 **9.88**、机身角速度 **0.27 °/s**（无 D 时 0.59）。
   代价是 ε RMS 7.3°→25.2°、视野内 100%→72%：**「只动头」是取舍，不是调参**。
5. 一个反直觉但很硬的发现：**按任务式子加的 D 项（用 `yaw_rate` 视线角速度）在
   "只动头"工况下是负作用**——分离比从 5.49 掉到 2.38、机身角速度从 0.59 升到
   1.41 °/s，因为它把头部的动作当成了机身的动作，反过来推机身。同一个增益、把
   头部角速度减掉，分离比 9.88、机身角速度 0.27。**D 项必须配头部角速度补偿。**

## 3. 符号：必须先说清楚，否则整个结论会反过来

固件 `yaw_u>0` 使机身 yaw **减小**（这是 P 项 `k_yaw*(yaw-q_head-stable_yaw)`
能构成负反馈的唯一自洽取法，REPORT §3 对同一条环路做过同样的推导）。于是：

```
ψ̈ = -d·ψ̇ + c·yaw_u,   c = yaw_sign·k_yaw_accel = -12.814
yaw_u = k_yaw·(ψ-ψref) - k_dyaw·ψ̇
⇒ Acl = [[0,1],[c·k_yaw, -d - c·k_dyaw]]，ωn = 7.16，2ζωn = d + c·k_dyaw
⇒ ζ = (1.2 - 12.814·k_dyaw)/14.27
```

所以 `k_dyaw > 0.0937` 就把 ζ 压到 0 以下。仿真里完全一致（6 种子，5 场景，4 控制器）：

| k_dyaw | +0.2 | +0.5 | +1 | +2 |
|---|---|---|---|---|
| ζ（解析） | -0.095 | -0.364 | -0.811 | -1.000 |
| ε RMS（CfC） | 39.1° | 101.5° | 103.7° | 103.7° |
| 成功率（CfC） | 27% | 9% | 8% | 8% |

**任务给的式子里起阻尼作用的是负的 `k_dyaw`**。因为真机的 `yaw` 极性从来没测过
（REPORT §7 第 1 条），`/cfg` 的钳位做成对称的 `[-8, 8]`，符号留给 30 分钟的上机实验定：

* 扶正后原地给一个小的 `vyaw` 参考（或手动轻推机身绕竖轴），看 `yaw-u` 增大还是减小；
* 或者直接看 `/status` 的 `imu.yaw_rate` 与 `/cfg` 的 `k_dyaw`，把 `k_dyaw` 设成 `-0.2`，
  推一下机身看航向环是"回中"还是"越推越走"。

## 5. 命令速率限幅（B）

设计照 smartcar `ActionRateLimiter` 的思想（执行侧削峰），三点与它的坑对齐：

1. 每 tick 最大变化量 = `rate_max * dt`，`dt` 用实测的循环周期（3 个
   `vTaskDelay(2)` + UART ⇒ 实际 6~10 ms，不是 2 ms）。
2. **吸附判据是 `|target| <= stop_eps`，不是 `target <= 下界 + stop_eps`**。
   后者在速度范围下探为负（倒车脱困/坡道防蠕行）时会把"全速倒车"读成"要停"，
   然后吸附到 0 —— 正是 `action_shaper.py` 里 `stop_speed` 那段注释记录的坑。
3. 安全壳任何一条保护（gaze / robot_state=0 / NaN / 视觉过期 / 命令超时 / flash 写入）
   触发的 tick，限幅器走 **snap 而不是斜坡**：保护不许排队。

仿真里的效果（默认 `vx_rate_max=1.0`、`vyaw_rate_max=400`）与"关掉"对比：

> 仿真的 `FirmwareParams.vx_rate_max/vyaw_rate_max` 默认是 **0（关）**，这样
> `eval.py` 能逐位复现本报告正文的基线（并行跑基线的人依赖这一点）；下面 ON 这一列
> 是 `scan_dyaw.py` / `diag_sep.py` 里显式传固件默认值（`FW_DEFAULTS`）跑出来的。

| 控制器 | 分离比 ON / OFF | ε RMS ON / OFF | jerk1 ON / OFF | 成功率 ON / OFF |
|---|---|---|---|---|
| cfc | 0.740 / 0.715 | 7.29 / 7.42 | 0.0140 / 0.0137 | 91.9% / 91.8% |
| teacher | 0.466 / 0.464 | 11.67 / 11.74 | 0.0055 / 0.0055 | 76.8% / 76.7% |
| pd | 1.261 / 1.256 | 22.05 / 22.26 | 0.0153 / 0.0153 | 48.1% / 47.7% |
| mlp | 0.415 / 0.456 | **66.86 / 92.48** | 0.0193 / 0.0183 | **25.6% / 15.5%** |

对已经平滑的两个控制器影响在种子噪声内（±3%），对最烂的 MLP 大幅改善（ε −28%）。
**它不改变"头身分离"这个结论**——削峰管的是执行抖动，不是对象阻尼。这也印证
`action_shaper` 的分工："本损失管生成平滑，limiter 管执行削峰"，两者都不管欠阻尼。

## 6. 训练侧：`λ_smooth` 已经有了，但几乎没在起作用

`train_cfc.py:247-256` 已经有 `smooth = mean((a[t+1]-a[t])²)`、`--lambda-smooth`
默认 **0.05**，与 `action_shaper.action_loss` 同一公式（都对 **pred** 的一阶差分），
每轮也打印 `smooth=…`。**不需要新增**。但 `probe_smooth.py` 在一个真实 batch 上量出来：

```
mse = 0.000929     smooth(原值) = 0.000071   ⇒ 动作帧间差分 RMS = 0.0084
λ·smooth = 0.000004（占 mse 的 0.4%）        total 0.049224 vs 0.049221（λ=0）
|∇mse| = 9.22e-02     |∇λ·smooth| = 1.47e-04   ← 梯度占比 0.16%
```

也就是说：这一项**存在、非零、进反传**（18 个张量有非零梯度），但权重比 mse 小
**600 倍**。原因是策略在训练分布上本来就已经很平滑（差分 RMS 0.008 vs 动作满量程 1），
没有可压的抖动。想让它在数量上"咬得住"，`λ` 要到 **~1.3** 才占 mse 的 10%
——但那是拿跟踪精度换平滑，而当前的 jerk 问题主要来自固件 `vyaw` 通道（REPORT §0.4
的行动项，已由 §5 的速率限幅处理），不是策略生成。**结论：不改 λ，另记一条**。

## 7. 「只动头」到底能不能做到（数字）

CfC，10 种子，5 场景。2×2 因子：机身指令（`vyaw gain`，1=真实控制器，0=消融）×
D 项用的角速度（视线 / 机身）。`k_dyaw=-0.3` 是除基线外的统一对照点。

| 配置 | 分离比 | ε RMS (°) | 成功率 | 视野内 | 机身ω（小误差区） |
|---|---|---|---|---|---|
| 现状：策略发 vyaw，无 D | 0.74 | 7.28 | 92.3% | 100% | 7.86 |
| 策略发 vyaw，D=视线角速度 | 0.88 | 7.56 | 90.4% | 100% | 6.50 |
| 策略发 vyaw，D=机身角速度 | **1.20** | 7.47 | 90.9% | 100% | 4.87 |
| 消融：策略不发 vyaw，无 D | 5.49 | 25.20 | 59.2% | 72.1% | 0.59 |
| 消融 + D=视线角速度 | **2.38**（更差） | 25.16 | 59.2% | 72.1% | **1.41**（更大） |
| 消融 + D=机身角速度 | **9.88** | 25.17 | 59.2% | 72.1% | **0.27** |

**回答：单独加阻尼不能做到。** 加 D 项把分离比从 **0.71 → 0.90**（任务式子）或
**→1.09~1.57**（减掉头部角速度），仍然 ≤1.6，离"机身基本不动"（≥5）差一个数量级。

**但"只动头"本身是能做到的 —— 需要三件事同时到位，缺一不可：**

1. **策略不再主动转机身**（消融里 `vyaw gain=0`：分离比 5.49）。这是训练/任务设计的取舍。
2. **D 项用机身角速度**（同一个消融 + 补偿：分离比 9.88、机身角速度再降一半）。
3. **接受几何代价**：头部 ±45°、FOV ±30°，而 orbit/mixed 里人的方位扫过 ±50°。
   机身不转 ⇒ 人出视野（`in_fov` 100%→72%）、ε RMS 7.3°→25.2°。所以"只动头"
   只在 **|方位| ≲ 30°** 的工况下成立。

剩下三条原因，按贡献排序：

1. **策略在主动转机身**（`head_share_cmd=0.383` ⇒ 62% 的指令行程是 vyaw）。这是
   训练/任务设计的取舍，不是固件缺陷。
2. **头部角速度污染 D 通道**（新发现，最值得先修）。`yaw_rate = -gyro_yaw_comp` 是
   **视线**角速度（IMU 装在头上）= 机身 + 头部。头部跟踪时它是几十 deg/s，直接进
   航向力矩。证据见上表最后两行：压掉机身指令后，视线角速度版的 D 反而把机身
   从 0.59 推到 1.41 °/s；减掉头部角速度后是 0.27。
3. **几何**：见上。

## 8. 推荐

* **`k_dyaw = -0.2`**（先做 §3 的符号台架实验；极性相反就用 `+0.2`）。
  理由：ζ 0.084→0.263；CfC 分离比 0.74→0.90 且 ε 只 +0.16°；教师 ε −45%、成功率
  +20pt；PD ε −77%、成功率 +48pt。**代价最小、收益最稳的一个点。**
  要更激进的平滑度可以到 `-0.3`（ζ 0.38），CfC 分离比 0.88、ε +0.28°。
* **配套必做（固件，价值最高）**：把 D 项的 `yaw_rate` 换成**机身**角速度
  （`yaw_rate - dq_head`）。`q_head` 有回读（`ReadMotorState(3)`），差分 + 一阶低通
  即可。理由不是"锦上添花"：**在"只动头"工况下，不补偿的 D 项是负作用**
  （分离比 5.49→2.38、机身角速度 0.59→1.41），补偿后变成 9.88 / 0.27。补偿后
  同增益的分离比在正常工况也翻倍（0.90→1.20）。注意差分的是 1° 量化的回读，
  噪声与滞后**没有**在本仿真里建模，收益是上界。
* **速率限幅**保持默认 `1.0 / 400`（对好控制器无影响，对 MLP 有大幅改善）。
* **训练侧不改**（§6），要动就单独一条 PR，并且必须先补上"小误差区抑制 vyaw"的代价项，
  否则只调 `λ_smooth` 是拿精度换平滑。

## 9. 局限（最脆弱的三条）

1. **最脆弱：`k_dyaw` 的符号依赖一个从未实测的极性。** `yaw_sign=-1` 是
   `params.py` 里为了让 `lqr_k2=+25` 构成负反馈而选的约定值（REPORT §7 第 1 条）。
   如果真机 `yaw` 的极性相反，`k_dyaw` 的符号要整个翻过来 —— 而**现在是 0，
   所以错也不会出事**；一旦上机填错符号，就是正反馈，比不加更糟。上机第一步必须是
   §3 那个 30 分钟实验。
2. **§7 的"减掉头部角速度"用的是真值 `qd_head`。** 固件只能从 1° 量化的 `q_head`
   回读差分，噪声/延迟都没建模，所以 1.09/1.40/1.57 是**上界**，不是预测值。
3. **所有绝对值都压在 `yaw_damping = 1.2 /s` 这个拍出来的数上**（REPORT §7 第 3 条）。
   真机摩擦更大 ⇒ ζ 更高、机身更安静 ⇒ 分离比的绝对值会更好看。**只有同一阻尼下
   的相对次序可信**，这条和 REPORT 原有的限制是同一条。
4. 台架只验证了编译、`/cfg` 读写与 `/status` 字段；`yaw_rate` 静止读 0（死区），
   速率限幅在横躺状态下**完全没法验证**。平衡行为一句都没验。
