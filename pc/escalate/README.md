## 2. 标签从哪来（本次最关键的设计问题）

三条路线，结论是 **C（A 做基础分布 + B 补时序场景）**，但理由不是"推荐 C"，
而是**A 和 B 各自的失败模式互不重叠**。

### 2.1 A 单独用（蒸馏）为什么不够

蒸馏的上限就是教师本身。`decision_hub` 的判据是 `p_esc = σ(b + Σ wₖφₖ(x))`，
**只读当前帧**。所以：

* 它给不了"连续 8 帧"这种标签 —— 在它眼里这 8 帧的 logit 一模一样；
* 用它当唯一监督，学生最好也只能复现"当前帧看起来怎样"，
  **永远不会学到"刚才发生了什么"**。

这不是理论担忧，是实测：本工程第一版只用 A（`--per-cell 0` 的等价做法），
时序对照 AUC 卡在 **0.52**（随机水平）——因为头学到的就是教师的逐帧函数。

### 2.2 B 单独用为什么不够

纯规则合成场景会缺失两件事：

1. **基率**。合成场景的阳性率由剧本决定，跟真实部署的稀有度无关；
   而升级头的**绝对概率**只在"和训练混合比例一致"时才有意义（§5.2）。
2. **校准锚点**。没有教师给的低概率区形状，头会把整片良性帧压成同一个数，
   ECE 直接 0.3+。

所以 A 提供"低概率区长什么样"，B 提供"时序证据长什么样"。

### 2.3 B 怎么构造：**孪生对照**（本次方法上的核心）

每个场景族都造 **一对**会话，`ordered` / `control`：

* 两者**逐帧字段的多重集完全相同**（同一批 donor 窗口、同一组覆盖值，
  只是顺序不同/方向相反/聚簇方式不同）；
* `ordered` 的时序谓词成立 → 硬标签 1；`control` 的同一谓词不成立 → 硬标签 0。

这带来一个**可证伪的对照**：任何只看当前帧的模型，在两边的输入分布**完全
相同**，所以它的 AUC 必然是 0.5。实测 B0（逐帧判据）在四个族上分别是
0.51 / 0.49 / 0.55 / 0.65 —— 除了 `sustained_conf` 之外都贴着 0.5。

四个族（每个 48 帧，50 Hz）：

| 族 | 时序证据 | `control` 怎么造 | 单帧模型为什么瞎 |
|---|---|---|---|
| `sustained_conf` | 连续 ≥8 帧 `conf<0.65`（0.60，单帧 `u_conf=0`） | 同样 16 高 + 32 低，改成 `[低,低,高]` 循环 → 最长连低 2 帧 | 单帧 conf=0.60 与"第 1 帧就 0.60"无从区分 |
| `bearing_rate` | `theta_img` 8 帧斜率 >5° 且 \|θ\|>10° | **同一条轨迹反向遍历**（人走进画面中心） | `theta_img` **不在任何势函数里** |
| `flicker` | 20 帧窗口内 ≥3 次短掉帧（每次 40~80 ms） | 掉帧总帧数相同，改成 4 次、间隔 11 帧 | 每次掉帧 `age<250ms` → `u_lost` 恒 0 |
| `conf_drift` | 16 帧内 `conf` 单调下滑 >0.03（全程 >0.85） | 同一条曲线反向（置信度在回升） | `c_local_ok` 恒 1、`u_conf` 恒 0 → φ 一字不变 |

真值由**时序谓词**给出（`_gt_runs` / `_gt_decline` / `_gt_window_count`），
不是蒸馏，因此不存在"用教师教学生再考教师"的循环论证。

> 一个必须承认的方法学细节：第一版**没有**让孪生对共用 donor 窗口，
> 结果 B2 基线在同一批数据上刷到 0.64 —— 那不是时序信息，是 donor 差异泄漏。
> 修正后（`esc_scenes.py::build_temporal_sessions` 里 `picks` 只抽一次）
> 才是现在这组数字。

### 2.4 训练目标

```
y = 硬标签（arm B 帧）/ 蒸馏软标签（arm A 帧）
L = 2.0·BCE(σ(escalate), y) + 3.0·[MSE(3 连续头) + CE(mode) + CE(emote)] + 0.01·mean(λ)
```

控制头损失只在 arm A 帧上算（时序帧的观测被改过，教师动作不再是它的标签）。
控制头**没有被学坏**：mode 准确率 0.9951（冻结基线 0.9909），连续头 MSE 也下降了。

## 3. 第 6 个头怎么接

* **共享同一个隐状态**：`escalate` 读的是保留门之后的 `h`，与另外 5 个头
  **完全同一个张量**（不是池化、不是第二路分支）。所以固件仍然只跑**一次**
  `cfc_step()`，第 6 个头就是 `64 + 1` 个 float。
* **blob**：`n_heads 5→6`，`head_dim[5]=1`，`head_act[5]=2`，
  `heads` 层 975→1040 float（+260 B），层 id 一个没动。
  `head_act=2` 的意思是"激活交给消费方"，`dim==1` 时消费方做 **sigmoid**
  （softmax 到 1 类恒等于 1，没有信息）。这样 `cfc_model.c` **一行都不用改**，
  老固件还能照常加载新 blob —— 详见 `FIRMWARE_CHANGES.md` §2。
* **头长按当前固件**：并行任务把 blob 头从 2240 改成了 **2256**（末尾追加
  `layer_prec[16]`），原有 18 个字段的偏移一个没动。本工程的 blob 是
  2256 头 + 全 0 的 `layer_prec`（全 float32），总 **133648 字节**，
  与 `pc/train/export_blob.py`（并行版）**逐字节一致**。
* **多任务**：升级损失与控制损失同时反传，主干只做微调（`--lr-trunk 3e-4`
  vs `--lr-head 3e-3`），唯一额外放开的是保留门 `ret`（`--lr-ret 3e-2`），
  理由见 §5.1。

## 4. 结果（`python test_escalate.py`，测试集 41 条会话 / 15744 帧）

### 4.1 蒸馏保真（arm A 帧，`GT = 逐帧判据 p_esc > 0.5`，n=3456）

| 模型 | AUC | ECE |
|---|---|---|
| B0 逐帧判据（被替换的那套） | 1.000 | 0.058 |
| B1 判据+EMA(τ=1 帧) | 1.000 | 0.057 |
| B2 手工时序特征 + 逻辑回归（48 维） | 1.000 | 0.202 |
| **CfC `escalate` 头** | **0.9997** | **0.033** |

判决一致率 **99.5%**（阈值 0.5），说明它确实把可观测的那部分判据学下来了，
而且顺带避免了 B2 那种"手工特征破坏概率含义"的问题（B2 的 ECE 0.20）。
Spearman 只有 0.31：**排序大体对，具体数值不是逐点复现** —— 因为同一个头还要
拟合 arm B 的硬标签，低概率区的形状被重新分配了（§5.2）。

### 4.2 时序优势（孪生对照，阳性 = `ordered` 的 GT=1，阴性 = `control` 全部帧）

| 族 | #pos | CfC | B0 判据 | B1 +EMA | B2 线性时序 |
|---|---|---|---|---|---|
| `bearing_rate`（φ 看不见） | 736 | **0.889** | 0.501 | 0.495 | 0.568 |
| `conf_drift`（φ 完全不变） | 1024 | **0.638** | 0.495 | 0.469 | 0.538 |
| `flicker`（u_lost 恒 0） | 512 | **0.667** | 0.551 | 0.589 | 0.596 |
| `sustained_conf`（φ 有水平、无长度） | 800 | 0.699 | 0.649 | **0.928** | **0.876** |
| **族宏平均** | | **0.723** | 0.549 | 0.620 | 0.645 |
| 混合（未匹配，池化） | | **0.755** | 0.496 | 0.510 | 0.664 |

三条基线都是**同一个头拿不到的东西**：B0 是现在的生产判据，B1 是"给判据加个
泄漏积分器"（τ 在验证集上选），B2 是"把 φ 的 EMA/差分摊开喂给逻辑回归"
（48 维，用与 CfC 相同的训练标签拟合）。

**怎么读这张表**：

* 纯逐帧判据（B0）在三个"φ 看不见"的族上贴着 0.5 —— 这是设计使然，可证伪。
* **B2 在 `sustained_conf` 上赢 CfC（0.876 vs 0.699）**：因为"连续低置信"这个
  证据**本来就是 φ 的函数**，手工加一个 `Δ8(c_local_ok)` 就够了。
  这条要如实说：**在"证据已经在势函数里、只差积分"的场合，手写特征比学出来的
  隐状态更省事、更准。**
* CfC 赢的地方是"证据根本不在 φ 里"（`theta_img` 的方位变化率、掉帧的聚簇方式）。
  这不是调参调出来的优势：`bearing_rate` 用**同一条轨迹的正反两个方向**做对照，
  逐帧字段多重集完全一致，任何逐帧模型的 AUC 必然是 0.5。

### 4.3 固定误报率下的召回

误报率的分母只能是**判据认为良性的帧**（`teacher<0.1`，test 上 3250 帧），
把"判据也说该升级"的帧算成误报是错的。

| 工作点 | 阈值 | test FPR | 时序召回 | 对照 B0 |
|---|---|---|---|---|
| FPR ≤ 1% | 0.383 | 1.26% | **0.201** | 0.012 |
| FPR ≤ 5% | 0.329 | 4.37% | **0.322** | — |

比逐帧判据好一个数量级（0.201 vs 0.012），但**绝对值不高**：因为时序片段被
故意建在良性 donor 上（判据 0.02~0.05），头的输出是"这件事该升级的概率"，
落在 0.2~0.6；而良性帧的高分尾部（判据本身 0.8+ 的真危险帧）把 1% 分位
推到了 0.38。**这是"混合了两类标签"的必然后果**（§5.2），不是模型没学会 ——
同一个头在孪生对照上能做到 0.72 的宏平均 AUC。

### 4.4 导出对拍

| 项 | 值 |
|---|---|
| blob | 133648 B（头 2256 + payload 131392），`n_heads=6`，`head_dim=[1,1,4,8,1,1]`，`head_act=[1,1,2,2,1,2]` |
| CRC32 | 自洽（`zlib` 口径，自身 4 字节当 0） |

## 5. 最脆弱的三点（按风险排序）

### 5.1 冻结主干的保留门 λ 几乎关着 → 隐状态几乎无记忆

这是本次最硬的发现，也是**第一版失败的直接原因**：

* 冻结 base 的 `ret` 训练出来是 `λ=0.043`，而 `h = u + λ(h_prev − u)`
  意味着**上一帧的贡献每帧衰减 95.7%**，有效记忆 ≈ 1 帧。
* 实测（`test_escalate.py` §7）：同一当前帧、前 24 帧置信度 0.60 vs 0.99，
  第一版 `|Δh|/|h| = 0.2%`、`|Δp_esc| = 0.0016` —— 一个"读 h 的线性头"在那种
  条件下**不可能**做时序判断。第一版时序 AUC 卡在 0.52 就是这么来的，
  而不是模型容量问题。
* 修法：把 `ret` 单独放进优化器（`--lr-ret 3e-2`）。`ret` 是**每单元一个标量**
  （64 个 float，blob 里本来就有这一层），所以单元可以分工：一部分保持
  `λ≈0`（控制要快），一部分涨到 `λ≈0.92`（升级头要历史）。
  训练后 `λ`：均值 **0.093** / 中位 **0.0031** / **最大 0.919** —— 确实分化了，
  同一条诊断变成 `|Δh|/|h| = 2.9%`、`|Δp_esc| = 0.032`。
* **风险仍在**：中位数还在 0.003，也就是说绝大多数单元对升级头没有历史贡献，
  真正干活的可能只有 5~10 个慢单元。上真机后如果 `ret` 被别的损失再拉回去，
  升级头会**静默退化成逐帧模型**。所以 `FIRMWARE_CHANGES.md` §6 建议把
  `λ` 的均值打进遥测 —— 它是"头还在不在工作"的最便宜的指标。

### 5.2 混合比例会移动绝对概率，`p_esc` 不是"世界给的常数"

训练集里 arm B（时序片段）占 50%，于是"一个看起来良性的帧"在训练分布里有
**相当一部分概率**属于某个升级片段。头的输出是这个**混合后验**，
所以它在 arm A 帧上的平均预测比逐帧判据高（实测 ECE **0.25**，且是**纯基率偏移**，
不是形状错：标定一个温度 + 一个偏置之后 ECE 降到 **0.026**，AUC 不变）。

* 这两个数**都能精确写进头本身**（`W/T`、`b/T + shift`），固件零改动；
* 部署时时序事件的实际发生率一变，**只要重拟一个 float**（`head_b[5]`）；
* 所以本文所有"绝对概率"的数字只在"训练混合比例 = 部署混合比例"时成立；
  **AUC / 固定误报率下的召回 / 阈值**这些不受影响。

### 5.3 12 个势函数里只有 7 个能从 106 维观测里算出来

`cfc_task.c::build_obs()` 的 106 维里**没有**语义通道，所以
`m_speech / m_point / m_stale_sem / p_multi / p_lookup` 这 5 个势函数
（"人在说话""指着东西""一句话多个动作""要查资料""语义通道过期"）
在本地判据里根本算不出来，本工程一律置 0。

* 所以这个头替换的是**可观测的那 7 个**：`u_conf / u_lost / u_clip / u_ood /
  s_irrev / s_approach / c_local_ok` —— 也就是 `esc_hub.c` 里手写 smoothstep
  最多的那一段（`FIRMWARE_CHANGES.md` §3 给了两种收编方式）；
* 剩下 5 个要么继续留在固件里当 5 个乘加，要么把观测扩到 113 维
  （`input_dim` 上限是 256，blob 装得下；`build_obs()` 要加 7 行）。
  **本工程没有做这件事**，因为那会把 blob 从"106 维"变成"113 维"，
  与并行任务里的固件版本对不上；
* 后果：**这个头永远不可能完全替代 `decision_hub` 的全量判据**。
  蒸馏的上限、时序的增益，都只在"可观测子空间"里成立。

## 7. 与 `decision_hub` 的边界（别混）

| 项 | `decision_hub` | 本工程 |
|---|---|---|
| `p_esc` 从哪来 | 12 势函数的可加 logistic（PC 上算，或固件里 ~150 周期） | 第 6 个头读 `h`，64 MAC + 1 次 expf |
| 用什么信息 | 当前帧的 12 个标量 | 当前帧的 106 维观测 **+ 隐状态里的历史** |
| 可归因 | logit 精确等于各 φ 贡献之和 | **不可精确归因**（只能看 λ/慢单元/对比消融） |
| 时序 | 对两个离散检测量做 `ema_tau=0.15` 的平滑 | 隐状态自带（`λ` 决定多久） |
| 层级路由 / 安全否决 | `U(L)=p_esc·P_fix−C_L`，`veto` | **不做**：头只出概率，路由仍在 `esc_hub.c` |
| 语义通道 5 项 | 有 | **没有**（§5.3） |

**建议的落地形态**（不是替代，是分工）：

```
固件 p_esc = σ( head_escalate(h) + Σ_{5 个语义势函数} wₖ·φₖ )     # 前者学出来，后者 5 个乘加
```

即：可观测的 7 个势函数由头接管（删掉那一大段 smoothstep 与权重表），
不可观测的 5 个继续当一行点积。这样固件少一套逻辑、判据仍然可解释。

## 8. 局限

1. **数据全是合成的**。arm A 是 `pc/train/data` 的 8 条教师闭环会话的只读副本，
   arm B 是在良性 donor 窗口上改标量通道构造的。真机上的 `feat_64`
   （YOLO + FeatureAdapter 的真输出）会整体改变隐状态分布，`input_mean/std`
   与 `λ` 都要重估；
2. **时序场景是"设计出来的"**，不是从真机失败案例里挖出来的。四个族的谓词
   （8 帧连低 / 8 帧斜率 5° / 20 帧 3 次掉帧 / 16 帧下滑 0.03）是工程判断，
   阈值本身应该用真实退化数据重标；
3. **孪生对照的构造方式限制了结论的范围**：它证明"存在一类只有时序模型能做
   的判别，且 CfC 学到了"，不证明"CfC 在所有真实时序场景上都更好"；
4. **只有对照，没有真值**。升级"该不该发生"最终由任务成败定义，本工程没有
   闭环任务成功率，只有判据与规则谓词；
5. `torch ↔ numpy` 对拍到 2e-6，但**没有过 C 引擎**（`pc/train` 那边有
   `hoststub` 可以直接编 `cfc_model.c` 加载本 blob，§FIRMWARE_CHANGES 7 列了
   该验的四条）。`head_act=2` 的 sigmoid 在消费方，这条口径必须由固件侧
   补齐才算真正闭环。
